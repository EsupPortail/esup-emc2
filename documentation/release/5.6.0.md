# Version 5.6.0 (XX/XX/2026)

## Changements 

[AMELIORATION]
* La ressource 'Corps' ne présentent plus globablement tous les agents, mais liste les agents sous la responsabilité de l'utilisateur connecté.
* La ressource 'Emploi-Type' ne présentent plus globablement tous les agents, mais liste les agents sous la responsabilité de l'utilisateur connecté.
* La ressource 'Grade' ne présentent plus globablement tous les agents, mais liste les agents sous la responsabilité de l'utilisateur connecté. 
* La ressource 'Spécialité' ne présentent plus globablement tous les agents, mais liste les agents sous la responsabilité de l'utilisateur connecté.
* Ajout d'une trame csv pour les chaînes hiérarchiques
* Les actions associées aux missions et activités des fiches métiers sont maintenant dans un bloc pour être affichées ensemble.
* Les tableaux de la section 'Ressources' conservent leur état lors de rafraichissements

[NOUVEAUTÉ]
* La modification d'une convocation à un entretien professionnel utilise un template différent de la convocation initiale.
* Nouveaux boutons pour purger les blocs Missions, Activités, Compétences et Applications des fiches métiers
* Possibilité de purger les ressources associées à un référentiel
* Les catégories statutaires des fiches métiers peuvent maintenant être multiples

## Changement de structure de la base de données

### Restructuration à faire avant de lancer les modifications en bdd

```postgresql

-- Nouvelles tables pour gérer la multiplicité des catégories et niveaux des fiches métiers
create table fichemetier_categorie
(
    id                    serial                  not null
        constraint fichemetier_categorie_pk
            primary key,
    fichemetier_id        integer                 not null
        constraint fichemetier_categorie_fichemetier_id_fk
            references fichemetier
            on delete cascade,
    categorie_id          integer                 not null
        constraint fichemetier_categorie_carriere_categorie_id_fk
            references carriere_categorie
            on delete cascade,
    complement            text,
    histo_creation        timestamp default now() not null,
    histo_createur_id     integer   default 0     not null
        constraint fichemetier_categorie_unicaen_utilisateur_user_id_fk
            references unicaen_utilisateur_user,
    histo_modification    timestamp,
    histo_modificateur_id integer
        constraint fichemetier_categorie_unicaen_utilisateur_user_id_fk_2
            references unicaen_utilisateur_user,
    histo_destruction     timestamp,
    histo_destructeur_id  integer
        constraint fichemetier_categorie_unicaen_utilisateur_user_id_fk_3
            references unicaen_utilisateur_user
);

-- reprise de données des fiches metiers
insert into fichemetier_categorie (fichemetier_id, categorie_id)
select id as fichemetier_id, categorie_id from fichemetier fm where categorie_id is not null;

-- retrait de colonne devenue inutile
alter table fichemetier drop column if exists categorie_id;
```

### Sans BddAdmin

```postgresql
-- Changement du comportement de la clef étrangère carriere_correspondance_type 
alter table carriere_correspondance
    drop constraint carriere_correspondance_carriere_correspondance_type_null_fk;

alter table carriere_correspondance
    add constraint carriere_correspondance_carriere_correspondance_type_null_fk
        foreign key (type_id) references carriere_correspondance_type
            on delete set null;
```

### Avec BddAdmin

```postgresql
-- Changement de la clef primaire de la table carriere_correspondance_type
CREATE SEQUENCE carriere_correspondance_type_id_seq START 100000;
ALTER TABLE carriere_correspondance_type
    ALTER COLUMN id SET DEFAULT nextval('carriere_correspondance_type_id_seq');
ALTER SEQUENCE carriere_correspondance_type_id_seq OWNED BY carriere_correspondance_type.id;
```
